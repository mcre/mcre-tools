# アリ観察の経路再探索

2026-10-08。フェロモンの道ができた後も、別の餌や短い経路を見つけられるように調整した。

## 変更

従来は前方が最大濃度の70%以上なら直進し、そうでなければ最も濃い方向へ曲がっていた。
現行は左右の濃度差に応じて、旋回量を滑らかに変える。通常のランダム旋回は残し、弱い勾配がある場所でも道から離れられるようにする。
各アリは生成時に0.7～1.3の感知係数`q`を持つ。センサ距離は`5 × q`セル、濃度の重みの指数は`k = 0.9 / q`。
左右の重みを`L^k`・`R^k`、前方を`2 × F^k`とし、重みの合計に対する左右差を旋回量にする。
全個体に反応と感知距離の違いがあり、固定割合の「探索役」は設けない。
旋回速度の上限は4から4.5rad/秒へ調整した。速度、個体数、通常のランダム旋回、餌の感知、付着・蒸発・拡散は維持する。

探索中は餌へのフェロモンをたどり巣へのフェロモンを残し、運搬中はその逆。
付着量は出発地点から実際に歩いた距離とともに減るため、短い経路ほど途中の付着が弱まりにくい。
弱い方向へ進む個体が新しい道を残し、それを他の個体が利用する余地を作る。
巣の方向、最短経路、近道の開く時刻はアリへ渡さない。
数学的な最短経路への収束を保証するモデルではない。

## 追加したマップ

定義はGit管理対象の`src/lib/ants/maps/*.json`。固定IDと日英の表示名を持ち、将来の選択UIでも利用できる。
マップはリセット横のメニューから選べる。地形と餌だけをJSONに置き、パラメータ・実験操作・乱数seedは別に管理する。

| ID         | 検証する状態                                                       |
| ---------- | ------------------------------------------------------------------ |
| `fork`     | 直進先の少量の餌が枯れた後、上下に分かれた両方の大きな餌へ移れるか |
| `loop`     | 壁の手前の餌が枯れた後、壁を回って奥の餌へ移れるか                 |
| `rooms`    | 最初の部屋の餌が枯れた後、別の開口を通って奥の部屋へ移れるか       |
| `shortcut` | 迂回路ができた後に開いた細い近道へ、帰りの道が移るか               |

`shortcut`の定義には近道がある。評価時だけ入口の14セルを壁で閉じ、240秒後に消しゴムと同じ処理で開く。
600秒間実行し、最後の120秒の成功した搬入を比較する。
近道の利用率は、運搬中に壁の右から左へ渡った場所を記録し、実際に巣へ搬入できた個体だけから集計する。
帰りの距離は餌取得から搬入までの実際の累積移動距離で、直線距離やセンサが示す方向ではない。
この観測情報はアリの移動・付着へ戻さない。

## 評価条件

世界240×160セル、300匹、固定1/30秒tick。全マップで共通のパラメータを使用する。
調整にはseed 17・29を使い、最後の検証には別の5seedを使用した。
確率的な方向選択と滑らかな旋回、濃い方向を優先する指数、反応とセンサの個体差、短時間の探索、センサ、旋回、付着の距離減衰、蒸発・拡散を比較した。
濃度上限の引き上げや付着量の低減だけでは、経路再探索と曲がった通路での採餌を両立できなかった。
時間を決めてフェロモンを無視する方式も比較したが、採用値では無効にしている。

搬入数だけによる順位は旧方式を高く評価するため、それだけでは採用しない。
近道の利用率と実際の移動距離、両方の分岐先の餌の回収を確認し、既存6マップの採餌・状態の有効性も検証する。
単体テストでは近道の利用率50%超、帰りの距離10%以上減、分岐先それぞれ10%超の回収を要求する。
以前の6マップの回帰テストの搬入数条件も維持した。

## 検証結果

調整に使っていないseed 1901・2003・2111・2203・2309で比較した。
変更前は5条件とも近道の利用率が0%。採用値の条件ごとの平均は64.0%。

| seed | 近道の利用率 | 開く前の帰りの実移動距離 | 最後の120秒の実移動距離 |
| ---- | -----------: | -----------------------: | ----------------------: |
| 1901 |        99.6% |                    291.1 |                   178.7 |
| 2003 |         6.6% |                    228.4 |                   289.4 |
| 2111 |        70.3% |                    238.9 |                   231.9 |
| 2203 |        99.3% |                    241.0 |                   225.0 |
| 2309 |        44.3% |                    250.7 |                   306.9 |

全5条件の成功した搬入をまとめると、帰りに実際に歩いた平均距離は247.9から236.0セルへ変わった。
近道の利用率が高くても、近道を渡る前後に余分に歩く場合があるため、利用率だけで最短化できたとは判定しない。
2条件では最後の120秒にも迂回路を多く利用した。すべての条件で最短経路へ収束する状態にはなっていない。

`fork`では両方の大きな餌を全5条件で回収し、回収の少ない側でも16.5%以上を取得した。
変更前の少ない側の取得は0.1～4.6%だった。
`loop`の平均搬入は611.4、`rooms`は127.4。別室の餌の搬入は少なく、複数の壁を挟む帰巣には課題が残る。

既存6マップを180秒で比較した。変更前は直前の搬入量を重視した既定値、採用値は経路の再探索を重視した値。

| マップ    | 変更前の平均搬入数 | 採用値の平均搬入数 | 採用値の最少搬入数 |
| --------- | -----------------: | -----------------: | -----------------: |
| open      |             2831.2 |             1855.0 |               1534 |
| detour    |             1768.8 |              863.0 |                801 |
| gap       |             1612.0 |             1151.2 |                985 |
| zigzag    |              501.0 |              387.2 |                126 |
| scattered |             2204.0 |             1722.2 |               1572 |
| far       |             1188.8 |              607.4 |                395 |

短時間の搬入量は減った。探索と採餌量は別の指標として残し、この低下を改善として扱わない。
旧来の2seedの回帰テストでは、記録された初回調整前の値から平均搬入量を各マップ95%以上に保ち、全体の評価値15%以上改善という条件を維持している。
追加検証100試行では、食料の総量、壁・外周、濃度の有限性・範囲をすべて満たした。

## 再実行

```sh
npm run ants:optimize -- --exploration
npm run ants:optimize -- --exploration --validate docs/ants-exploration-results.json
npm run ants:optimize -- --exploration --validate docs/ants-exploration-results.json --regression
npm run test:unit -- src/tests/vitest/unit/antsAdaptiveRoutes.spec.ts src/tests/vitest/unit/antsOptimization.spec.ts
```

`tools/ants/exploration-baseline.json`は変更前の濃度最大を選ぶ方式の値。
`exploration-protocol.json`は探索候補・検証seed・実行時間・近道を開く操作を固定する。
`ants-exploration-results.json`には採用値、変更前の値、評価条件、ソースのハッシュ、候補の順位とマップ別の集計結果を保存する。
`candidateId`は評価条件内の候補IDを指し、各候補のパラメータは変更前の値にその候補の設定を重ねて復元できる。
近道の利用率はseedごとの率の平均、帰りの距離は搬入数で重み付けした平均を記録する。各試行の時系列データはGitに保存しない。
今回の詳細データは`output/playwright/ants/optimization/exploration-results-detailed.json`に移した。このファイルはGit管理対象外で、再検証には集計結果JSONの採用値を使用する。
コマンドはマップや既定パラメータを書き換えず、結果をignoredの`output/playwright/ants/optimization/`へ出力する。
