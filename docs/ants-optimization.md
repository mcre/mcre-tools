## 評価

- 開放地、壁の迂回、狭い通路、折り返しの壁、分散した餌、遠くの餌の6種類。
- 世界240×160セル、300匹。時間は実時間ではなく固定tickのモデル時間。
- 最初に36組を90秒×2seedで比較し、上位と近傍18組を180秒×2seedで比較。重複を除くと48組、計648試行。
- 探索seedは17、29。最初の候補を101、211、307、401、503で比較した後、餌の枯渇後の動きも確認した。
- 3分間の評価差が0.3%だった上位2候補のうち、枯渇後の回収が良かった候補を採用し、新たな809、919、1009、1103、1201で元の値と比較した。最終検証60試行。

## 餌が少ない場合の追加確認

`scattered`を1セル20個（合計1560個）にして、seed 601・701、600秒で新旧を比較した。
最初の候補ではseed 701で256個残ったが、蒸発を速めた採用候補では両試行とも1560個すべてを搬入した。
変更前は地面の餌が0となったが、運搬中が34・21個残った。全4比較試行の質量保存と状態も確認した。
短時間の搬入数だけでは枯渇後の探索を評価できないため、この追加確認を採用判断に使い、seed 701の枯渇後の回収を回帰テストに残した。

## 再実行

```sh
npm run ants:optimize -- --baseline
npm run ants:optimize
npm run ants:optimize -- --validate docs/ants-optimization-results.json
npm run ants:optimize -- --validate docs/ants-optimization-results.json --depletion
npm run test:unit -- src/tests/vitest/unit/antsOptimization.spec.ts
```

`tools/ants/protocol.json`に範囲・seed・時間、`baseline.json`に変更前の値を固定している。
通常の探索コマンドは3分間の搬入数による上位候補を出力する。今回の最終値は、上位2候補を別途`--validate`と`--depletion`で比較して決めた。
結果はignoredの`output/playwright/ants/optimization/`へ出力する。コマンドはマップや既定値を書き換えない。
回帰テストの`baseline-reference.json`は調整前に測定した結果で、探索コマンドから自動更新しない。
